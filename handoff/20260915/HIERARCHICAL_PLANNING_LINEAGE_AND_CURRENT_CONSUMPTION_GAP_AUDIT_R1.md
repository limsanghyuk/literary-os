## 1. Historical lineage already exists

### 1.1 2026-06-23/24 Macro planner / Synopsis Assembler
The project explicitly defined the North Star as whole-series writer-room replacement, not isolated scene generation.

The Synopsis Assembler design required:
- logline;
- theme/aboutness;
- characters and relationships;
- central conflict;
- causal spine;
- macro arc;
- episode beats and hooks;
- subplot tracks;
- tone/genre profile.

It also identified the causal spine as a first-class output and distinguished main/subplot responsibility.

### 1.2 2026-07-04 Four-layer reverse-fill
The project formally defined the four planning layers:
- FullSeriesArc;
- EpisodeArc;
- SequenceBlueprint;
- SceneBlueprint.

It identified SequenceBlueprint as the top-down bottleneck and defined a sequence by `goal + obstacle + value_shift + turn`, not by location or work step.

The authored anchor later confirmed approximately 8-10 value-shift sequences per episode and preserved fine-grained `turn_type` plus normalized `turn_class`.

### 1.3 2026-08-06/08 Macro Planning Reanchor and consumption audit
The project found that deterministic sequence formulas had been standing in for actual dramatic judgment.

The reanchor established:
- runtime/minute formulas answer only "how many", not "why this sequence";
- human authored `sequence_intent`, `goal`, `obstacle`, `value_shift` are mostly unique semantic judgments;
- sequence boundaries are value-change boundaries;
- planner judgment must be restored above deterministic sizing.

The schema-consumption audit then found the deeper engineering problem:
`the layers existed, but the consumer contract had never been adequately negotiated/wired`.

This is a direct historical predecessor of the current defect.

### 1.4 Subplot Allocator research
The project separately specified a Subplot Allocator whose purpose was to decide:
- which supporting characters own parallel development in an episode;
- their target share;
- group focus;
- whether subplot and main plot cross.

Therefore multi-story weaving and supporting-character ownership were already explicit research targets.

### 1.5 2026-09-07 Narrative Operating Engine / Closed Loop
The master blueprint restored a single canonical hierarchy:
`Narrative State Kernel -> Series/Episode Planning -> Ensemble/Ecology/Event Ownership -> Sequence Plan -> Scene Plan -> Surface -> Diagnostics -> Responsible Ancestor -> Re-lowering -> State Commit`.

The episode production protocol explicitly required:
- Series/Writer-room Check;
- Episode Architecture with acts/major movements, midpoint, reversals, climax and exit state;
- Ensemble Ecology / Event Ownership;
- Candidate Portfolio / Selector before sequence commitment;
- Sequence goal/function, cast, event, information movement, relationship movement, thread/payoff operation, value shift/turn, exit obligation and scene budget;
- Scene function, POV/focality, participants, conflict/pressure, ordered beats, information action, relationship action, physical/subtext target, entry/exit state;
- global audit including escalation, midpoint/climax, ensemble balance and crossing plot/relationship axes.

## 2. Current E6/R3 contract regression

### 2.1 E6-R3B retained only a subset
R3B improved important lower-level defects:
- no fixed 4-person/6-utterance topology;
- more direct agency;
- resident choice;
- visible failure/attempt chains;
- remote/cross-cut continuity.

However the sealed R3B episode contract primarily contains:
- one episode `objective`;
- entry state;
- target exit;
- nine sequences each with title + `goal` + five scenes;
- scene contracts with `dramatic_owner`, speech act, obligation and turn.

The following historically researched upper-layer obligations are not explicit first-class frozen contracts in R3B:
- series long-range function / remaining-run pressure;
- episode dramatic question;
- episode function inside series;
- central conflict axis as a dramatic axis rather than operational objective;
- act/major-movement design;
- midpoint/reversal/climax architecture contract;
- independent A/B/C or equivalent multi-story axes;
- subplot debt allocation;
- per-sequence POV/plot ownership as an upper-plan obligation;
- per-sequence obstacle;
- explicit `value_shift {from,to}`;
- turn type/class;
- per-sequence relationship/thread/info operations as required fields;
- explicit story-axis convergence/collision design;
- candidate portfolio alternatives before sequence commitment.

### 2.2 What this causes
When the strongest upper field is one operational objective, lowering naturally becomes work decomposition:
`objective -> operational subtask 1 -> subtask 2 -> ... -> completion`.

Even if individual scenes contain good resident choice, relationship movement and visible action, they remain branches of one parent task instead of independently alive narrative tracks.

This explains the user's observation that a 60-minute episode can feel like many small field problems rather than a drama about a world, protagonists, supporting characters and conflicting lives.
