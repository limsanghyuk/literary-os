## 3. Defect register and closure decision

### D01 — Validator mistaken for generator
**Defect:** R53 upper-layer physical overlay validates already-formed architecture but does not generate the new architecture.

**Closure:** Reclassify UL overlay evidence as `VALIDATION/GOVERNANCE CAPABILITY`, not `GENERATIVE QUALITY`. Any future Candidate qualification must name and hash the actual planner implementation that produced the plans.

### D02 — Episode axis compression
Current `EpisodeSynopsisPlan.v0.3-r1` schema constrains 2–3 episode axes, while the current 1,160-plan corpus contains 1–5 axes and substantial one-axis flattening.

Distribution:
- 1 axis: 178 episodes;
- 2 axes: 269;
- 3 axes: 685;
- 4 axes: 25;
- 5 axes: 3.

One axis owns >=75% of sequence allocations in about `33.62%` of episodes and owns 100% in about `15.34%`.

**Closure:** `EpisodeSynopsisPlan.v0.3-r1` is frozen as **LEGACY / REVERSE-ENGINEERED ANALYTIC ONLY** for Candidate forward generation. It must not be the new Candidate generation contract.

### D03 — Schema/consumer drift
Among 1,124 records declaring `EpisodeSynopsisPlan.v0.3-r1`, 170 violate the declared 2–3-axis cardinality. Full schema validation found 663/1,124 records failing at least one declared schema condition because the data evolved while retaining the old schema identity.

**Closure:** No schema ID may be retained after semantic field/rule mutation. New forward planning uses a new schema/version. Every physical build must run 100% schema conformance tests on produced plans.

### D04 — Singular sequence owner
Old sequence allocation assigns one owner per sequence, while authored sequences commonly carry several simultaneous obligations.

**Closure:** Replace singular axis ownership with `primary_owner + co_owners + obligation_ids[]`. A sequence is a **dramatic transaction**, not an axis bucket.

### D05 — Non-operational defer
`deferred` is nonempty in 1,006/1,160 plans, but no sequence allocation uses a `DEFERRED:DF#` owner.

**Closure:** `DEFER` becomes an episode-level portfolio disposition with reason, cost, horizon and re-entry conditions. It is forbidden as a fake sequence owner.

### D06 — Fixed structural quotas in legacy runtime
Legacy/runtime helpers contain defaults/validators around 16 episodes, 10 sequences and 50 scenes, including a 10x5 scene grid in one architecture validator.

**Closure:** Candidate forward planning forbids fixed episode/sequence/scene/axis counts. Human-corpus counts are diagnostics/priors only, never generation quotas.

### D07 — No complete forward Scene Plan contract
`RUNTIME_SCENE_PROJECTION_V1` is a useful projection but is not a complete forward Scene Planner.

**Closure:** New forward Scene Transaction contract must bind necessity, actors, goal/opposition, physical action, information/relationship transaction, pre-state, post-state, downstream consumer, merge/split test and subtext constraint before surface rendering.

### D08 — DB semantic availability != causal adoption
DB64 A2 remains `PENDING_ENGINE_CAUSAL_ADOPTION_EXPERIMENT`.

**Closure:** No claim that DB information improves generation is allowed until intervention tests prove plan changes caused by changed relationship/event/information/social/payoff state.

### D09 — Social ecology is not uniformly complete
Explicit social-ecology evidence is available in only a subset of the audited 61 works (19/61 in the currently visible consumer-ready path).

**Closure:** `SOCIAL_GROUP` obligations are provenance-aware and conditional. The engine must not hallucinate a fully observed group-state graph when the source is absent. Missing group-state evidence becomes an explicit unknown/derivation task.

### D10 — Surface research advanced ahead of architecture qualification
Recent surface work assumed more upper-layer stability than was demonstrated.

**Closure:** Surface rendering remains a downstream concern. Promotion research order is reset to:
`State -> Obligation Portfolio -> Episode Architecture -> Sequence Transactions -> Scene Transactions -> Surface`.
