## 1. Governance decision
The I4K program is accepted as a **promoted research architecture** for Literary OS development.

This promotion means the project no longer treats Narrative Event Ecology as an optional isolated experiment or a one-shot plot-injection utility. The accepted research direction is a higher-level narrative operating architecture in which character state, relationships, social/institutional mechanisms, environmental/chance mechanisms, world state and future-thread ownership interact to generate, propagate, select and adopt narrative events.

Target progression:
1. `Narrative State / Planning / Realization / Repair OS`
2. `Narrative Event Ecology Engine`
3. `Narrative Showrunner Operating System`

The long-term objective is a system closer to a functioning literary writers-room ecology: multiple character/relationship/world forces remain active, interact autonomously, generate candidate events, propagate consequences and allow a higher-order selector/showrunner layer to decide what enters the work.

## 3. Repair-forward doctrine
`FAIL` and `HOLD` remain immutable under their original preregistrations. However, a downstream defect does not automatically demote a higher-level architecture when evidence localizes the defect to a narrower implementation boundary.

Therefore:
- preserve successful structural layers as protected invariants;
- localize defects to the narrowest supported layer;
- repair that layer in a fresh preregistered experiment;
- never lower thresholds or relabel old FAIL/HOLD;
- never discard Event Ecology merely because renderer/surface realization fails;
- never promote defective literal outputs or episode prose as canonical engine policy.

For the current I4K-5 result, the repair target is the `Plan -> Surface` boundary, not Event Ecology itself.
