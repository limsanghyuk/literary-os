## 0. 이 문서가 정하는 것

지금까지 후판(thick_sequence) 편입 게이트는 **구조·정합·근거**만 검사했다. 스키마 키가 맞는지, `member_scene_nos`가 SceneCard와 일치하는지, `evidence_refs`가 원문 행을 가리키는지. 이 세 가지를 전부 통과하고도 **내용이 비어 있는** 후판이 편입되었다(101번째프로포즈). 게이트에 **깊이 항이 없었던 것**이 원인이다.

2026-08-10 검증으로 다음이 실측 확인되었다.

> 같은 작품·같은 씬·같은 근거를 주고, 후판의 **내용 텍스트만** 정형문으로 바꾸면, 그 후판으로 쓴 씬은 원문에서 멀어진다. 판정자 3인 블라인드 강제선택 24문항에서 원본 후판 22승 2패(p=0.00002).

즉 **후판의 깊이는 문체 취향이 아니라 성능 지표**다. 그래서 이 문서는 (1) 무엇이 합격이고 (2) 실패작을 어떻게 고치고 (3) 무엇을 본떠 쓸지를 지정한다.

## 2. 왜 얕아지는가 — 실패 유형 4종

실측 결과 얕음은 한 가지가 아니라 **네 가지 서로 다른 고장**이었다. 처방이 다르므로 반드시 구분한다.

### F1. 골격 충전 — 문장 뼈대를 미리 정하고 빈칸만 채운다
`101번째프로포즈` 전형. 명제 1,593개 중 96.4%가 서로 같은 골격의 반복이고, 빈칸에 들어간 값은 대부분 **SceneCard 표제**다(명제표제인용 100%).

> 실제: "'억울함을 삼키는 달재' 장면의 상실·실패가 박달재에게 앞선 선택의 대가를 체감시키고 이후 결정의 무게를 키운다."

이 문장은 어느 작품 어느 장면에도 붙는다. 원문을 읽지 않아도 쓸 수 있고, 따라서 **원문 정보를 하나도 옮기지 않는다**. 진단 신호: 정형문% 높음 + 표제인용% 높음.

### F2. 상위 필드 복사 — event 문장을 cast·plant_payoff가 되받아 쓴다
`너의목소리가들려` 전형. cast 88.9% · 회수 100%가 `event` 문장의 재기술이다.

> 실제 cast: "어춘심는 혜성의 진실감각과 삶의 윤리를 지탱하는 가족·돌봄축으로서 … **이 시퀀스에서는 쫓겨난 춘심과 혜성이 대석의 권위에 책을 불태우는 방식으로 항의하고 …**"

앞부분은 **작품 전체 고정 역할 설명**(모든 시퀀스에서 동일), 뒷부분은 **event 문장 그대로**다. 결과적으로 cast 필드에 "이 인물이 이 시퀀스에서 무엇을 원하고 무엇을 잃는가"가 **한 글자도 없다**. 필드 수는 채워졌으나 정보량은 event 하나뿐. 진단 신호: 재기술% 높음, 정형문%는 오히려 낮음(복사는 반복이 아니므로 골격 검사에 안 걸린다 — 그래서 이 항목이 따로 필요하다).

### F3. 표제 나열 — 인과 대신 씬 제목을 이어 붙인다
`개와늑대의시간` 전형(표제인용 92.4%).

> 실제 event: "'지우, 엄마 걱정을 전하다'에서 … 장면이다, 이어 '낙제 부모들의 취한 고백'에서 … 장면이다, 마지막으로 '지우를 위한 목조각을 숨기는 수현'에서 … 장면이다"

씬 세 개를 `, 이어 / 마지막으로`로 연결했을 뿐 **하나가 다음을 낳는 인과가 없다**. 시퀀스는 씬의 목록이 아니라 하나의 압력이 형성되고 뒤집히는 단위다. 진단 신호: 표제인용% 높음 + 정보보유%·회수보유% 낮음(인과가 없으니 정보 이동도 없다).

### F4. 정형 꼬리 — 내용 뒤에 기능 라벨을 상투구로 덧댄다
`강남엄마따라잡기` 전형(상투 피복 77.0%).

> 실제 명제: "'민주가 시험 난도를 숨기다'에서 민주는 … 자부심을 지키려 한다. **이 장면은 현재 시퀀스의 인물·환경 전제를 구체화한다.**"
> 실제 info_shift before: "현민주는 '민주가 시험 난도를 숨기다' 직전까지 **관련 사실이 다른 인물에게 드러날 위험을 관리해야 하는 상태다.**"

앞 절은 진짜 내용인데 뒤 절이 라벨 상투구다. 특히 `info_shift.before`가 통째로 상투구가 되면 정보 이동은 **before/after 대비가 사라져** 아무것도 말하지 않는다. 강남엄마따라잡기는 event 다양도 0.748·cast 다양도 0.783으로 상위 필드는 멀쩡한데 명제와 info에서만 무너졌다. 진단 신호: 상투피복% 높음 + info 다양도만 낮음.

## 3. 기준작 — 경성스캔들

**기준작으로 경성스캔들을 지정한다.** 선정 사유는 세 가지다.

1. 11작 중 다양도 최고(0.799)이며 보조 진단 11항 전부 통과한 유일한 작품이다.
2. 무엇보다, **깊이가 실험으로 검증된 유일한 후판**이다. 2026-08-10 2AFC의 ARM H가 바로 이 작품의 후판이고, 기계 열화판을 22:2로 이겼다. 다른 합격작들은 같은 자를 통과했을 뿐 렌더 성능이 대조된 적이 없다.
3. 인물 3인 이상·정보 반전·장기축 회수가 한 시퀀스 안에 공존하는 사례가 풍부해 본보기로 쓰기 좋다.

차선: 결혼못하는남자(0.779). 다양도는 2위이고 문장 형태가 매우 건조·간결해 **모방 난이도가 낮다**. 다만 회수보유 67.2%로 장기축 심기·회수가 성긴 편이라, 회수 필드는 경성스캔들을 봐야 한다.

### 3-1. 합격 형태 — `경성스캔들_01_S04` 전문 발췌

아래는 실제 편입본이다. 각 필드가 **무엇을 담고 무엇을 담지 않는지** 표시했다.

**event** — 씬 목록이 아니라 3단 인과 + 반전 + 대가:
> "순사들이 여경의 집에서 가방을 찾아오자 강구는 비밀번호를 대라고 몰아붙인다. 지라시팀은 발뺌 작전을 짜지만 완만 경찰서에 남겨지고, 가방이 열리는 순간 정치 자료 대신 미국 포르노 잡지가 쏟아진다. 여경에 대한 즉각적 조직 혐의는 무너지고 완은 자기 사생활이 공개되는 굴욕을 대신 떠안는다."

→ 압박(가방 압수) → 시도(발뺌·완 잔류) → 개봉이라는 **되돌릴 수 없는 사건** → 그 결과 **누가 무엇을 얻고 누가 무엇을 잃었는지**까지. 씬 표제 인용 0회.

**cast** — 인물마다 **이 시퀀스에서의 목표와 그 목표가 어떻게 배신당하는가**:
> 나여경 / PRIMARY / "가방을 자기 임무 물건이라고 끝까지 우기지만 비밀번호를 알 수 없어 폭로 직전까지 몰린다."
> 선우완 / PRIMARY / "지라시팀을 보호하려 경찰서에 들어가 즉흥적 거짓말을 준비하다 가방의 실제 내용 때문에 의도치 않게 여경의 정치 혐의를 벗긴다."
> 이강구 / OPPOSITION / "가방을 직접 열어 여경의 배후를 입증하려 하지만 포르노 잡지라는 결과 때문에 수사 우위를 잃는다."

→ 세 문장 모두 **"…하려 하지만/…하다가 …때문에 …된다"** 구조. 즉 욕망과 그 좌절이 한 문장 안에 들어 있다. **역할 상수 설명("변호축으로서", "가족·돌봄축으로서")이 없고, event 문장을 되받지 않는다.** 이 두 가지가 F2를 막는 핵심이다.

**info_shift** — subject를 `인물:대상`으로 잡고 before/after를 **서로 모순되는 두 명제**로:
> subject "이강구:가방"
> before "여경이 숨긴 가방은 반일 조직의 물증일 가능성이 높다."
> after "가방 안에는 정치 자료가 아니라 완의 포르노 잡지가 들어 있어 이번 압수만으로 여경의 조직 혐의를 입증할 수 없게 된다."
> mode REVEAL / scene_nos [21,23,25]

→ before가 **"…를 아직 모르는 상태다" 같은 상투구가 아니라 그 인물이 실제로 믿고 있던 내용**이다. after를 지우고 before만 읽어도 하나의 주장으로 성립해야 한다. 이것이 F4를 막는다.

**plant_payoff** — 장기축 이름 + 이번 회차가 그 축에 **무엇을 했는지**:
> PAYOFF / GS_bag_misidentification / "경성역에서 시작된 가방 오인은 경찰서 개봉으로 정체가 밝혀지며 즉각적 오해는 해소되지만 두 사람의 감정·수사 관계를 남긴다."
> CALLBACK / GS_wan_political_conversion / "정치 위험을 피하려는 완의 사적 물건이 역설적으로 여경을 정치 혐의에서 구해 그의 비정치적 삶이 독립운동선과 처음 실질적으로 접촉한다."

→ "이 지점은 X의 PLANT로서 장기 인과의 출발 조건을 심는다" 같은 **라벨 문장이 아니라**, 축의 상태 변화를 서술한다.

**scene_notes.functional_propositions** — 씬마다 **그 씬이 아니면 성립하지 않는 기능** 1~2개:
> s19 "순사들이 책장을 뒤엎는 수색으로 해화당이 지식·교육 공간인 동시에 식민 권력이 의심하는 정치 공간임을 물리적으로 보여준다."
> s20 "지라시팀이 가방을 포기하자고 결의하는 순간 집사가 경찰에 신고해, 회피 선택이 외부인의 선의 때문에 무너지는 코미디 역전을 만든다."

→ 씬 표제를 인용하지 않고 **씬 안에서 실제로 벌어지는 동작**을 쓴다. 명제를 다른 씬에 옮겨 붙이면 거짓이 되어야 한다. 이것이 명제가 진짜 정보를 담고 있다는 유일한 시험이다.

### 3-2. 금지 표현 목록

아래 어구가 산출물에 나타나면 그 문장은 십중팔구 빈 문장이다. 검색해서 지운 뒤 원문을 다시 읽고 쓴다.

- `…장면이다` 로 끝나는 event 절 / `이어 …, 마지막으로 …` 로 씬을 잇는 구성
- `'표제'에서 …` 로 시작하는 명제 (표제는 근거 필드에 넣고 본문에서는 사건 자체를 쓴다)
- `이 장면은 현재 시퀀스의 인물·환경 전제를 구체화한다` 류의 기능 라벨 꼬리
- `…직전까지 관련 사실이 다른 인물에게 드러날 위험을 관리해야 하는 상태다` 류의 before 상투구
- `…축으로서 핵심 선택에 필요한 정보·돌봄·협업 또는 반응을 제공해` 류의 역할 상수 서두
- `이 지점은 X의 PLANT로서 장기 인과의 출발 조건을 심는다` 류의 회수 라벨
- `‘A’에서 ‘B’로 이동시킨다` 골격에 SceneCard 표제만 바꿔 끼우는 방식

## 4. 저작 절차 — 회차 1편을 후판으로 만드는 순서

씬을 잘 쓰는 문제는 이미 해결되어 있다(CT-07, 후판 직접 렌더 r=1.63 > 사람 씬카드 1.00). 남은 문제는 **회차의 내용을 시퀀스 단위로 어떻게 구성하는가**뿐이다. 순서 배치가 아니라 **구성** — 각 시퀀스가 무엇을 말할지 결정하는 일이다.

**1단계 · 원문 통독(필수).** SceneCard만 보고 후판을 쓰지 않는다. 위 4가지 실패 유형은 전부 "원문 대신 SceneCard 표제를 재료로 삼았을 때" 발생한다. SceneCard는 씬 경계와 근거 좌표를 확인하는 용도이지 내용의 출처가 아니다.

**2단계 · 회차 명제 한 줄.** "이 회차는 무엇을 말하는가"를 한 문장으로 적는다. 이것이 시퀀스 분할의 기준이 된다.

**3단계 · 시퀀스 경계 결정.** 경계는 장소·시간이 아니라 **하나의 압력이 만들어져 해소되거나 뒤집히는 지점**이다. 한 시퀀스 안에서 (a) 누가 무엇을 걸고 (b) 어떤 되돌릴 수 없는 사건이 일어나 (c) 누가 무엇을 잃는지가 성립해야 한다. 성립하지 않으면 경계를 다시 잡는다. 회차당 시퀀스 수는 합격 6작 실측 기준 회당 6.6~11.8개(중앙값 9.9)다.

**4단계 · 필드 저작 — 반드시 이 순서로.**
`event` → `info_shift` → `cast` → `plant_payoff` → `scene_notes`

이 순서를 지키는 이유: event를 먼저 쓰고 나머지를 나중에 쓰면 **event를 복사하고 싶은 유혹**이 생긴다(F2). 그래서 event 직후에 info_shift를 써서 "이 시퀀스가 옮기는 정보"를 독립적으로 확정하고, cast는 **info_shift에 등장한 인물의 인식 변화를 행동으로 환산**해서 쓴다. cast를 쓸 때 event 문장을 화면에서 가려라.

**5단계 · 자기 시험 3문.** 각 필드를 쓴 뒤 다음을 통과하지 못하면 다시 쓴다.
- 치환 시험: 이 문장에서 인물명과 표제를 지우고 다른 작품에 붙여도 말이 되는가? 되면 빈 문장이다.
- 삭제 시험: 이 필드를 지웠을 때 시퀀스의 정보가 실제로 줄어드는가? 안 줄면 상위 필드의 복사다.
- 반증 시험: `info_shift.before`만 읽고 그것이 틀렸다고 말할 수 있는가? 없으면 before가 상투구다.

**6단계 · 근거 결속.** `evidence_refs`는 `SOURCE`(정본 원문의 행 범위)와 `SCENECARD`를 모두 단다. 행 번호는 **정본 원문 파일(CRLF·빈 줄 포함, 무가공)** 기준이다. 정규화 사본으로 세지 않는다 — 결혼못하는남자가 이 이유로 보류되었다. `source_hashes`에는 실제 원문 파일의 sha256을 넣는다. `UNBOUND_CURRENT_RUNTIME` 같은 자리표시자는 편입 불가다.

**7단계 · 제출 전 자체 채점.** §6의 `selfcheck.py`를 돌려 주판정 합격 + 보조 FLAG 2항 이하일 때만 제출한다.

## 5. 작품별 보강 처방

### 5-1. 101번째프로포즈 — 전면 재저작 (15회차 · 184시퀀스 · 1,593명제)
**진단.** 다양도 0.248, 정형문 96.4%, 표제인용 100%, event·cast·info 다양도 각 0.175 / 0.067 / 0.087. 전 필드가 골격이다.
**처방.** 부분 수정이 불가능하다. 남길 것은 `seq_id`·`member_scene_nos`·`evidence_refs` 좌표뿐이고 **6개 내용 필드는 전량 폐기 후 원문에서 다시 쓴다**. §4 절차를 처음부터 적용한다.
**주의.** 이 후판은 현재 정본에 편입되어 있으며 2026-08-10 검증 발효 조치에 따라 **격리 대상**이다. 재저작본이 §6 게이트를 통과하기 전까지 어떤 실험의 입력으로도 쓰지 않는다.
**우선순위 최하.** 재저작 비용이 신규 1작과 같으므로, 미저작 작품이 남아 있다면 그쪽이 먼저다.

### 5-2. 너의목소리가들려 — cast·plant_payoff 국소 재저작 (18회차 · 122시퀀스)
**진단.** event 다양도 0.764로 **event는 합격 수준이다.** 무너진 곳은 cast(0.510, 재기술 88.9%)와 plant_payoff(재기술 100%)뿐. 즉 사건은 제대로 읽었는데 인물과 장기축을 event 복사로 때웠다.
**처방.** event·info_shift·scene_notes는 **손대지 않는다.** cast 전량과 plant_payoff.statement 전량을 다시 쓴다.
- cast: 역할 상수 서두("…축으로서")를 전부 삭제하고, 인물별로 **이 시퀀스에서의 즉시 목표 + 그것이 좌절·변형되는 방식**을 한 문장으로. §3-1 cast 형태를 그대로 따른다.
- plant_payoff: event 문장 복사를 지우고, 해당 `thread_id`가 **이 시퀀스에서 어떤 상태 변화를 겪었는지**만 쓴다.
- 추가로 정보보유 63.9% → info_shift가 없는 시퀀스 44개를 점검한다. 정보 이동이 정말 없다면 시퀀스 경계가 잘못 잡힌 것이다(3단계 재검토).
**예상 작업량.** cast 579건 + plant_payoff 296건(실측). 6필드 중 2필드이므로 전면 재저작의 3분의 1 수준.

### 5-3. 개와늑대의시간 — 시퀀스 경계 재검토 + 전 필드 재저작 (16회차 · 143시퀀스)
**진단.** 가장 복합적이다. 표제인용 92.4%(F3) + cast재기술 53.3%·회수재기술 79.0%(F2) + info 다양도 0.452·정보보유 36.4%·회수보유 55.9%. event가 씬 표제의 나열이라 **애초에 시퀀스가 하나의 압력 단위가 아니다.**
**처방.** 필드 수리로는 해결되지 않는다. **3단계(경계 결정)부터 다시 한다.** 현재 143개 경계를 원문 기준으로 재검토하고, "되돌릴 수 없는 사건"이 없는 시퀀스는 인접 시퀀스와 병합하거나 분할한다. 경계 확정 후 §4 4단계 순서로 전 필드 재저작.
**우선순위 중.** 101번째프로포즈보다는 낫지만 사실상 재저작에 가깝다.

### 5-4. 강남엄마따라잡기 — 명제·info_shift 국소 재저작 (18회차 · 154시퀀스)
**진단.** event 0.748·cast 0.783으로 **상위 두 필드는 합격선 수준**이다. 무너진 곳은 명제(상투피복 77.0%, 표제인용 83.9%)와 info_shift(다양도 0.618). 전형적 F4 — 진짜 내용을 쓰고 뒤에 라벨 상투구를 덧댔다.
**처방.**
- 명제: `'표제'에서` 도입부와 `이 장면은 …한다` 꼬리 절을 **기계적으로 제거**한 뒤, 남은 알맹이가 그 씬 고유의 기능을 말하는지 확인한다. 알맹이가 남지 않는 명제만 다시 쓴다. 실측상 명제재기술 23.0%이므로 **약 4분의 1만 재저작**하면 된다.
- info_shift: `before` 전량 점검. "…직전까지 …상태다" 상투구를 인물이 실제로 믿던 명제로 교체한다. 이것만으로 info 다양도가 크게 오른다.
- 회수보유 66.2% → 회수 없는 52개 시퀀스 점검.
**우선순위 최상.** 투입 대비 회수가 가장 크다. 상위 필드가 살아 있으므로 재료(원문 독해)가 이미 확보되어 있다는 뜻이다.

### 5-5. 가을동화 — 부분 보강 (16회차 · 114시퀀스)
**진단.** 0.714로 합격선에 0.034 미달. 정형문 2.1%·재기술 17.2%로 **고장 유형이 뚜렷하지 않다.** event 0.626·cast 0.606이 낮은데, 문장이 상투적이어서가 아니라 **짧고 성기기** 때문이다.
**처방.** 재저작이 아니라 **밀도 보강**. event에 결과 절(누가 무엇을 잃었는가)을, cast에 좌절 절(…하려 하지만 …)을 추가한다. 명제(0.714 기여)는 손대지 않는다.
**단, 이 작품은 마지막에 한다.** 검증된 것은 "정형문으로 채운 후판은 성능이 낮다"이지 "0.748 미만은 전부 나쁘다"가 아니다. 합격선 자체는 앵커 1점(CT-07R T팔)에서 온 값이며 검증되지 않았다. 경계 근처 작품에 대한 개입은 근거가 가장 약하다.

### 5-6. 결혼못하는남자 · 공주가돌아왔다 — 내용 보강 불필요, 근거 좌표만 수리
두 작품 모두 **깊이는 합격이다**(0.779 / 0.766). 보류 사유는 전적으로 근거 결속이다. **내용 필드를 다시 쓰지 말 것.**

- **결혼못하는남자**: 2,607개 `:L…` 앵커가 **정규화 사본**(빈 줄 제거 + 우측 공백 절삭) 기준으로 매겨져 정본 원문과 어긋난다. 정본 대조 표본 일치 0/40. "빈 줄 제거 + rstrip" 가설로는 16회차 중 14회차가 정확히 일치하고 01·02회만 ±1 어긋난다. 두 경로 중 택일: ① 정본 원문(CRLF·빈 줄 포함) 기준으로 앵커 재산출, ② 01·02회 불일치 원인 규명 후 결정적 리맵 스크립트 적용 + 표본 재검증. **①을 권장한다** — 리맵은 재현 가능성이 검증에 의존하지만 재산출은 결정적이다.
- **공주가돌아왔다**: `source_hashes`가 160시퀀스 전부 `UNBOUND_CURRENT_RUNTIME`이고 행 앵커가 0개(씬 마커 1,467개뿐)다. SceneCard 수준 정합은 유지되나 채점 규약 v2 G4(판단 단위별 근거 행 인용)를 만족할 수 없다. 정본 원문 기준 행 앵커 부여 + `source_text_sha256` 결속으로 재산출한다.
- 부가: 공주가돌아왔다는 회수보유 27.5% · 정보보유 52.5%로 합격 6작 중 최저다. 근거 수리와 함께 **회수·정보가 비어 있는 시퀀스의 경계를 재검토**할 것을 권한다(필수 아님).

동봉 `selfcheck.py`를 쓴다. 외부 의존 없음(파이썬 표준 라이브러리만).


**주판정 (합격/불합격을 가르는 유일한 항)**
- `다양도@813 ≥ 0.748`

**보조 진단 (합격 여부를 바꾸지 않는다. 무엇을 고칠지 국소화하는 용도)**

| 항목 | 기준 | 걸리면 의심할 고장 |
|---|---|---|
| 정형문% | ≤ 6.0 | F1 골격 충전 |
| 상투피복% | ≤ 20.0 | F4 정형 꼬리 |
| cast재기술% | ≤ 20.0 | F2 상위필드 복사 |
| 회수재기술% | ≤ 20.0 | F2 |
| 명제재기술% | ≤ 25.0 | F2 |
| 명제표제인용% | ≤ 25.0 | F1 · F3 |
| 회수보유% | ≥ 70.0 | 시퀀스 경계 오설정 |
| 정보보유% | ≥ 70.0 | 시퀀스 경계 오설정 |
| event/cast/info 다양도 | 각 ≥ 0.70 | 해당 필드 국소 고장 |

**제출 조건: 주판정 합격 + 보조 FLAG 2항 이하.** 기준작 경성스캔들은 FLAG 0항, 난폭한로맨스는 1항이다.

보조 기준의 지위를 오해하지 말 것: 이 수치들은 합격 6작의 실측 분포에서 뽑은 것이지 실험으로 검증된 선이 아니다. FLAG는 "여기를 보라"는 신호이지 판정이 아니다. 반대로 **주판정 0.748은 검증 대상이었던 축**이므로 협상 대상이 아니다.

편입 게이트에도 같은 주판정 항이 추가된다. 회차 단위 다양도 하한을 통과하지 못한 회차는 작품 전체가 보류된다.

## 8. 이 지시서의 한계 (반드시 병기)

1. 깊이 축의 방향은 검증되었으나 **합격선 0.748이라는 값 자체는 검증되지 않았다.** 이 수치는 렌더 성능이 실증된 유일한 후판(CT-07R T팔)의 실측치를 앵커로 삼은 것이다. 따라서 0.714(가을동화)와 0.749(난폭한로맨스)의 차이를 품질 차이로 단정하지 말 것.
2. 검증은 **경성스캔들 1작**에서만 이루어졌다. 다른 작품·장르에서 같은 크기의 효과가 난다는 증거는 없다.
3. 열화는 **기계적으로** 만들어졌다. 사람이나 LLM이 실제로 얕게 쓸 때의 얕음과 같은 종류인지는 검증되지 않았다. 다만 §2의 4개 실패 유형은 기계 열화가 아니라 **실제 산출물에서 관측된 것**이므로 이 한계의 영향을 덜 받는다.
4. 2AFC는 상대 비교다. **절대 품질을 측정하지 않는다.** 22승이 "충분히 깊다"를 뜻하지 않는다.
5. 보조 진단 9항은 합격 6작의 분포에서 사후적으로 뽑은 값이다. **사전 등록되지 않았고 검증되지 않았다.**
6. 본 지시서에는 **확증 트랙 번호(CT-)를 부여하지 않는다.** CT-08A-R 판정이 나기 전까지 확증 트랙을 불리지 않는다는 원칙에 따른다.
