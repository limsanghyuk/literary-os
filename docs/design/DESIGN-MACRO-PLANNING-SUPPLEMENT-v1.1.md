# DESIGN-MACRO-PLANNING-SUPPLEMENT-v1.1 — 회차·시퀀스의 기획·구상·설계·창작 4단 정의 (2026-08-07, 집)

- 상태: PROPOSAL(재정박 v1의 보충) · 기준: `DESIGN-MACRO-PLANNING-REANCHOR-v1`(8/6, 회사) + 개발자 대화록(8/5~7) + **CT-06H 실측(56bd902, r=0.211 불성립)**
- 성격: 재정박 v1이 "왜 이 층이 비어 있는가"를 밝혔다면, 본 문서는 **개발자가 물은 "회차와 시퀀스를 각각 기획→구상→설계→창작해야 하지 않는가"에 4단 구조로 답하고, CT-06H가 확정한 인코딩 결함의 처방을 붙인다.**

## 1. 확인된 사실 기반 (대화록·실측 전수 종합)
1. 회차 내부 구조는 회차 수와 무관하게 일정(8~9시퀀스/60~67씬) — 회차 수는 총량이지 구조가 아니다. 작품 간 분산 66.7% = 작품 고유 리듬 실재 = **학습 대상 존재**.
2. 경계의 "왜"는 이미 코퍼스 언어 필드에 적혀 있다(sequence_intent 16,059/16,060 고유) — 분석은 답을 갖고 있다.
3. **그러나 현행 5필드는 생성 원천으로 얇다** — CT-06H: 생성 카드는 goal만 간헐 전달, **conflict·info 0건**, r=0.21. CT-02(잉여)와 수렴.
4. 프런티어는 씬(국소)에 강하고 회차 분할(전역·비가역 결정)은 미검증. 과잉 정돈(CT-03 FAIL 원인)은 구조층에서 증폭 위험 — 판별자 선행의 근거.
5. 설계층에 인물 필드 0 — 개발자가 정의한 시퀀스 기획의 요체("각 시퀀스에 등장하는 인물과 사건, 배경, 지문·대사 고려")가 스키마에 없다.

## 2. 4단 정의 — 두 층 각각 (개발자 질문에 대한 직접 답)
**[회차 수준]**
- 기획(WHAT): 전체 시놉 → 이 회차의 극적질문(DQ)·회차 기능·입구/출구 상태. 자산: episodearc 1,814건(존재·검증됨).
- 구상(HOW-거시): 막 구조·긴장 배분·인물별 노출 예산(load 층 연결)·전 회차와의 인계.
- 설계(STRUCTURE): **시퀀스 수·경계 위치·씬/분량 배분** — 현행 결정론 공식(sequence_planner, 470버전 동결·실측과 2배 괴리) 퇴역 대상. 이양 경로=S3(판단 언어화)→S2(경계 판별자)→학습.
- 창작(HANDOFF): 시퀀스 설계서 발행 — 아래층의 입력.
**[시퀀스 수준]**
- 기획: 회차 DQ로부터 이 시퀀스의 의도·기능 (현행 sequence_intent — 유지).
- 구상: **인물(누가 나와 무엇을 원하는가)·사건 구체·정보 이동(누가 무엇을 알게 되는가)** — 현행 부재, 신설 대상.
- 설계: **후판(厚版) blueprint** — 현행 5필드 + 신설 5필드: `cast[]`(인물·욕구) / `event`(사건 구체) / `info_shift` / `plant_payoff[]` / `scene_budget`(기존 승격). 신설 5는 CT-06H 정답표 5범주(goal·character·conflict·info·link)와 동형 — **측정이 찾아낸 결손을 스키마로 승격**하는 것.
- 창작: 씬카드 생성 (CT-06H의 재시험 지점).
