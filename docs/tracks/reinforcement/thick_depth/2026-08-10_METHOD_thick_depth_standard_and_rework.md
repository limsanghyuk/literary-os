# 후판(thick_sequence) 깊이 기준과 재저작 방법 — 방법 문서

- 발행: 2026-08-10 (KST 기준 2026-08-11 00시대 작성)
- 표준 ID: `LOS-DEPTH-STD-V0.1` / 지시서 ID: `LOS-THICK-AUTHORING-DIRECTIVE-V1.0`
- 적용 대상: `reinforcement_v1/thick_sequence/**` (후판 사이드카)
- 성격: 본 문서는 **방법과 절차**만 기술한다. 판정 수치는 결과 문서에, 남은 작업은 HANDOFF에 있다.

## 1. 무엇을 재는가

후판의 품질을 "문체"가 아니라 **성능 지표**로 잡는다.

- **주판정 1항 — 어절 다양도@813**: 회차/작품의 6개 내용 필드 텍스트를 어절로 분해하고, 길이 정규화 리샘플(N=813 어절, 30회 반복, seed 7)한 뒤 타입/토큰 비를 낸다. 합격선 **≥ 0.748**.
- 이 축만 실험으로 검증되어 있다: 동일 작품 내 열화 대조 2AFC, ARM H **22/24, p=2e-5** (`PREREG_DEPTH_VALID_20260810` / `RESULT_DEPTH_VALID_20260810`).
- **보조 진단 11항(FLAG)** 은 판정이 아니라 고장 위치를 가리키는 계기판이다: 정형문% ≤6 · 상투피복% ≤20 · cast재기술% ≤20 · 회수재기술% ≤20 · 명제재기술% ≤25 · 명제표제인용% ≤25 · 회수보유% ≥70 · 정보보유% ≥70 · event/cast/info 다양도 각 ≥0.70.
- **제출 조건 = 주판정 합격 + FLAG ≤ 2항.**

측정 도구는 표준 라이브러리만 사용한다. `selfcheck.py <thick_sequence 폴더> [stock300.json]`.

## 2. 얕음은 한 종류가 아니다 — 실패 유형 4종

실측 산출물에서 관측된 네 가지 고장이다. 처방이 서로 다르므로 유형을 먼저 확정하고 손을 대야 한다.

- **F1 골격 충전** — 문장 뼈대를 고정해 두고 SceneCard 표제로 빈칸만 채운다. 관측: 101번째프로포즈(정형문 96.4%, 표제인용 100%). 처방: 전면 재저작.
- **F2 상위필드 복사** — event 문장을 cast·plant_payoff가 그대로 되받는다. 관측: 너의목소리가들려(cast재기술 88.9%, 회수재기술 100%). **정형문 검사에 걸리지 않는다**(복사는 반복이 아니다). 처방: 저작 순서 강제 + 재기술% 항 상시 감시.
- **F3 표제 나열** — event가 씬 표제를 `, 이어 / 마지막으로` 로 이은 목록이다. 관측: 개와늑대의시간(표제인용 92.4%). 인과가 없어 정보보유 36.4%·회수보유 55.9%. 처방: 필드 수리로는 회복되지 않으며 시퀀스 경계부터 재설정해야 한다.
- **F4 정형 꼬리** — 실제 내용 뒤에 기능 라벨 상투구가 붙는다. 관측: 강남엄마따라잡기(상투피복 77.0%). event·cast 다양도는 멀쩡하므로 **명제와 info.before만 고치면 된다** — 투입 대비 회수 1순위.

### 2-1. 기계적 제거는 해법이 아니다 (반증 실측)
상투 꼬리를 문자열 수준에서 잘라내는 striptest 를 돌린 결과 강남엄마따라잡기는 0.594 → **0.619** 에 그쳤다. 합격선 0.748 에 한참 못 미친다. **얕음은 군더더기가 붙어서가 아니라 내용이 없어서 생긴다.** 따라서 처방은 삭제가 아니라 저작이다.

## 3. 무엇을 고칠 수 있고 무엇을 건드리면 안 되는가 (좌표 불변 계약)

가변 표면은 **내용 6필드뿐**이다.

```
event
cast[].desire_or_function
info_shift[].before
info_shift[].after
plant_payoff[].statement
scene_notes[].functional_propositions
```

나머지는 전부 좌표이며 1바이트도 바뀌면 안 된다: `schema` `work_id` `episode_no` `seq_id` `seq_index` `member_scene_nos` `evidence_refs` `source_hashes` `by`, cast 의 `character`/`participation`/`evidence_refs`, info 의 `subject`/`mode`/`scene_nos`/`evidence_refs`, plant 의 `kind`/`thread_id`/`scene_nos`/`existing_refs`/`evidence_refs`, scene_notes 의 `scene_no`/`evidence_refs`.
**배열 길이와 순서, 씬별 명제 개수도 좌표다.** 이 계약 덕분에 재저작은 SceneCard·정본과의 정합을 깨지 않는다.

## 4. 정답 형태 (기준작 = 경성스캔들)

기준작 선정 사유: 다양도 최고 0.799 + 보조 11항 전부 통과 + 깊이가 실험으로 검증된 유일 후판.

- **cast**: "…하려 하지만 …때문에 …된다" — 욕망과 좌절을 한 문장에. 역할 상수("형사인 그는")로 시작하지 않는다.
- **info_shift.before**: "모르는 상태다" 같은 상투구가 아니라 **인물이 그 시점에 실제로 믿고 있던 명제**.
- **명제(functional_propositions)**: 다른 씬으로 옮기면 거짓이 되어야 한다. 이것이 실질/정형 판별의 조작적 기준이다.
- 금지: 씬 표제 인용, `이어 / 마지막으로` 나열, 기능 라벨 꼬리.

## 5. 저작 순서 강제

```
event → info_shift → cast → plant_payoff → scene_notes
```
event 직후에 cast 를 쓰면 F2(상위필드 복사)가 사실상 보장된다. cast 를 쓸 때 event 를 가리는 것이 F2 차단의 핵심이다.

## 6. 집행 절차 (재현 가능한 4단계)

1. **패킷 생성** — `mkpacket.py` 가 회차별 `*.packet.json` 을 만든다. 시퀀스마다 `seq_id`·`seq_index`·`member_scene_nos`·cast 순서(`characters`)·`participation`·`info_subjects`/`info_modes`·plant `kind`/`thread_id`·씬별 `n_props` 와 **원문 축자 슬라이스**를 담는다. 저작자는 이 패킷만 보고 쓴다.
2. **저작** — 시퀀스별 JSON(`event`/`cast[]`/`info_before[]`/`info_after[]`/`plant[]`/`props{씬번호:[...]}`)을 작성한다.
3. **병합 + 좌표 게이트** — `merge.py <작품> <회차2자리>` 가 6필드를 위치 기반으로 주입한 뒤 좌표 전체를 원본과 대조한다. **하나라도 어긋나면 아무것도 쓰지 않고 exit 1.**
4. **측정** — `check_ep.py <작품> <회차>` 로 회차 단위 다양도/FLAG 를 낸다. ≥0.748 까지 2·3·4 반복.

## 7. 병렬 위임 절차 (실증됨)

저작 표준(`AGENT_BRIEF.md`) + 기준편 1개(실제 집필된 회차) + 기계 게이트(merge/selfcheck) 세 가지를 묶어 주면 대량 저작을 Sonnet 병렬 에이전트에 넘길 수 있다. 실증: 8 에이전트 · 17회차(강남 02–18) 동시 집행 → **전 회차 1회차 통과**, 다양도 0.803–0.864, 좌표 오류 0건.

주의 — 위임 프롬프트에 반드시 포함할 것:
- 파일 생성은 **bash heredoc 으로만**. `C:\claude\...` 경로에 대한 Write/Edit 는 조용히 잘린다.
- 회수보유% FLAG 는 회차 단위에서 해소 대상이 아니다(§8).

## 8. 명시적 한계

- 합격선 0.748 이라는 **값 자체는 미검증**이다(앵커 1점). 검증된 것은 "이 축이 깊이를 가른다"는 것이지 "0.748이 옳은 절단점"이라는 것이 아니다.
- 2AFC 검증은 경성스캔들 1작에서만 이뤄졌다.
- 보조 11항은 합격 6작 분포에서 **사후 추출**되었고 사전등록이 없다. FLAG 를 판정으로 쓰면 안 되는 이유다.
- **회수보유% 는 구조적으로 해소 불가**: 정본에서 `plant_payoff` 배열이 빈 시퀀스에는 배열 길이 불변 계약상 항목을 넣을 수 없다. 회차 단위 재저작으로 올릴 수 있는 값이 아니며, 올리려면 후판 스키마의 회수 입도 자체를 다시 협상해야 한다.
- F1~F4 는 기계 열화가 아니라 **실제 산출물에서 관측**된 것이라 열화-대조 실험의 일반화 한계를 덜 받는다.
- CT 번호 미부여. 본 작업은 확증 트랙이 아니라 보강 트랙이다.

## 9. 원문 취급

패킷과 저작 중간 산출물은 **원문 축자 슬라이스를 포함**한다. 따라서 `rework/**/packets/`, `rework/authored/` 는 공개 허브에 올리지 않는다. 허브에는 방법·결과·도구만 올린다.
