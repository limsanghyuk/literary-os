# 확증 트랙 — 방법 매뉴얼 v1.0

**문서 ID**: LOS-CT-METHOD-V1.0 · 2026-08-05

CT-01·CT-02를 집행하며 실제로 쓴 절차만 적는다. 이론이 아니라 재현 지침이다.

---

## 1. 사전등록서 서식

렌더 이전에 작성해 커밋한다. 필수 절(節)은 여덟 개다.

1. **검정 가설** — H1, H2… 각각 한 문장. "좋아진다"가 아니라 "무엇이 무엇보다 얼마나".
2. **재료와 조건** — 조건표. 조건마다 무엇을 주고 무엇을 안 주는지 명시.
3. **표본과 추출 규칙** — 홀드아웃 목록을 **결정론적 규칙**으로 정한다.
   CT-03 예: 시퀀스당 `member[0]`과 `member[len//2]`. 사람이 고르면 무효.
4. **1차 종점 1개** — 여러 개면 다중비교 문제가 생긴다. 공동 1차는 최대 2개까지.
5. **임계값** — 숫자로. "유의미한 개선" 같은 말은 금지. 예: `Δ ≥ 0.5`.
6. **2차 종점** — 판정에 쓰지 않고 기전 해석에만 쓴다.
7. **이 시험이 할 수 없는 것** — 결과가 나오기 전에 쓴다. 나온 뒤에 쓰면 변명이 된다.
8. **무엇이 이 시험을 무효로 만드는가** — 자기 파기 조건.

## 2. 네거티브 컨트롤 만드는 법 — 본 트랙의 핵심 장치

가장 흔한 착각: "설계도를 주니 좋아졌다" → 실은 "프롬프트가 길어지니 좋아졌다"일 수 있다.

**방법.** 같은 회차 안에서 **다른 씬/다른 시퀀스의 설계도**를 가져다 라벨만 대상 것으로 바꾼다.
필드 구성·필드 수·총 분량이 실험 조건과 같아야 하며, 내용만 틀려야 한다.

**해석표.**

| 관측 | 결론 |
|---|---|
| B > N 이고 N ≈ A | 작동한 것은 **저작 내용**이다. (CT-01) |
| B ≈ N > A | 작동한 것은 형식·분량이다. 저작 내용은 무의미. |
| B ≈ N ≈ A | 층이 조향력을 갖지 못한다. (CT-02) |
| N < A | 틀린 설계도가 해롭다 = 층에 조향력이 있다. (CT-01: 환각 40 vs 35) |

CT-02에서 **N이 A보다 나쁘지 않았다는 것**(환각 73 vs 75)이 FAIL의 진짜 근거다.
틀린 설계도가 해를 못 끼친다는 것은 그 층이 아예 읽히지 않는다는 뜻이다.

## 3. 블라인드 절차

1. 렌더 완료 후 각 산출물에 무작위 ID를 부여한다.
2. 조건 라벨·파일명 단서를 제거하고 `blind/` 로 복사한다.
3. 대상(씬/시퀀스) 내부에서 순서를 무작위화한다.
4. 매핑을 `SEALED_MAP.json` 에 기록하고 **채점 종료 전에는 읽지 않는다.**
5. 채점자는 별도 서브에이전트로 띄운다(원문·타조건 미열람).
6. 채점 파일 확정 후 개봉 스크립트를 돌린다.

**CT-03에서 추가된 것 — 라틴방격.** 같은 대상의 여러 판본을 한 채점자가 보면 비교로
출처가 드러난다. 대상 *i*, 채점자 *j* → 판본 `(i+j) mod 3`. 한 채점자는 각 대상을
정확히 한 판본만 본다. 채점자에게 조건 수·판본 존재를 알리지 않는다.

**CT-03에서 추가된 것 — 보정 앵커.** LLM 채점자는 모든 텍스트를 중앙값으로 몰아준다.
본 채점 전에 의도적 저품질 2건 + 홀드아웃 외부 고품질 2건을 먼저 채점시키고,
사전 기대 구간을 벗어나면 해당 채점자 결과를 무효 처리한다.

## 4. 정답표(rubric) 작성

원문만 본 **별도 추출자**가 만든다. 렌더러·채점자와 격리한다.

- CT-01(씬): 씬당 8~11개 구체 사실요소. 총 96요소.
- CT-02(시퀀스): 고정 8범주(목표·장애·가치이동 시작/종료·전환점 내용/위치·정보상태·인과연결)
  × 시퀀스 = 120요소. **범주를 고정해야 범주별 회수율을 볼 수 있다.**

점수는 `5.0 × matched / n_elements` 로 환산한다.

## 5. 통계 — 작은 표본에서 쓰는 것만

n=10~24에서 t검정은 부적절하다. 두 가지만 쓴다.

**부트스트랩 95% CI** (재표본 20,000, 시드 고정):

```python
def boot(d, n=20000, seed=20260804):
    random.seed(seed)
    ms = sorted(st.mean(random.choices(d, k=len(d))) for _ in range(n))
    return ms[int(.025*n)], ms[int(.975*n)]
```

**부호검정** (동점은 제외하고 n에서 뺀다):

```python
def signtest(d):
    pos = sum(1 for x in d if x > 0); neg = sum(1 for x in d if x < 0)
    n = pos + neg; k = max(pos, neg)
    p = 2*sum(comb(n, i) for i in range(k, n+1)) / 2**n
    return pos, neg, min(1.0, p)
```

**동점이 많으면 부호검정은 무력하다.** CT-02는 12개 중 동점 5개라 p=1.00이 나왔다.
이 경우 CI를 주 근거로 읽고, 부호검정은 보조로만 인용한다.

**민감도 검사 의무.** 단일 대상이 신호를 끌고 가는지 확인한다.
CT-02: 가장 큰 양수 하나(한성 S05, +2.00)를 빼면 나머지 11개 Δ가 **+0.09**로 붕괴했다.
이 검사를 안 했으면 "+0.250, 8범주 중 2범주 우세"로 통과라고 쓸 수 있었다.

## 6. 결함 공시 규약

집행 중 발견된 결함은 **유리·불리 무관하게 전량 기재**하고, 사후 규칙 변경으로 덮지 않는다.

CT-02 실제 예:
- `turn_position` 오프바이원(건빵 B군 9본). 상대위치는 정답이었으나 **사후 채점규칙 변경을 거부**했다.
  3조건에 대칭으로 작용하므로 판정에 영향 없음을 근거로 그대로 뒀다.
- `한성_S07__D3` 5,026B 절단. 개봉해보니 N′ 조건이었다 — 즉 B′를 부풀리는 방향이 아니었다.
  **개봉 전에 기재**했다는 점이 중요하다.

## 7. 디렉터리 규격

```
{실험ID}_run_{YYYYMMDD}/
  manifest.json        추출 규칙과 대상 목록
  holdout_raw.json     홀드아웃 원자료 참조(경로만)
  orig/                원문 발췌  ← 허브 커밋 금지
  prompts/             조건별 프롬프트 전량
  renders/             생성물 {대상}__{조건}.txt
  blind/               라벨 제거·재명명본
  SEALED_MAP.json      봉인 매핑
  key_{작품}.json      정답표
  score_{작품}_{채점자}.json
  RESULT_rows.json / RESULT_deltas.json
```
