# CT-07 사전등록 — 설계 깊이 응답 곡선 (2026-08-07, 집, 데이터 생성 전 고정)

**문서 ID**: LOS-CT07-PREREG-V1.0 · 근거: 개발자 지시(08-07) "설계대로 실험을 진행하라" · 상위: CT-06H(r=0.21)·해석 정정(13f8206)·거시기획 보충 v1.1(f3432c8)
**질문**: 시퀀스 설계의 깊이를 어디까지 올리면 사람 씬카드와 같은 기능 전달이 나오는가. 그리고 부족은 **정보량**인가 **생성 능력**인가.

## 1. 팔 구성 (같은 홀드아웃 10씬·같은 정답표 49요소·같은 렌더 사양)
| 팔 | 설계도 | 렌더 입력 | 신규 |
|---|---|---|---|
| A | 없음 | CT-06H renders_A **재사용** | 재채점만 |
| B | 사람 씬카드 | CT-06H renders_B **재사용** | 재채점만 |
| **L2-D** | 후판 blueprint 10필드(사람 저작) **직접** | base+후판 설계도 블록 | 렌더 10 |
| **L2-G** | 후판 blueprint → **GPT-5 생성 씬카드** | base+생성 카드 | 생성 65+렌더 10 |
| **L3** | 최대 깊이 = 정답표 요소 목록 자체를 카드로(B‴ 천장) | base+요소 카드 | 렌더 10 |
- 렌더 재사용 근거: 채점 배치 효과가 교란 핵심(CT-06 개정 1) — **50본 전부를 단일 블라인드 배치에서 신규 채점**하므로 A·B 재채점값이 이 배치의 앵커가 된다. 렌더러 사양은 CT-06H와 동일(Sonnet 격리·동일 템플릿·900±300자).
- **후판 10필드**: 현행 5 + cast[](인물·욕구)/event(사건 구체)/info_shift(누가 무엇을 알게 되는가)/plant_payoff[]/scene_note(씬별 1행 배분). 저작자=격리 서브에이전트(원문+박판 blueprint만 열람, **정답표 비접촉**). 저작물은 생성 전 sha 봉인.
- L3는 생성 없이 직접 렌더(천장 측정이 목적 — 생성 손실 배제).

## 2. 종점·판정 (사전 고정)
1차 종점: 기능충실(5.0×matched/n, 3인 중앙값). 유효성 게이트: 본 배치 **B−A ≥ 0.5**(미달 시 측정 무효 선언).
r_X=(X−A)/(B−A)로 각 팔 산출. 판독 규칙:
- **r_L2G ≥ 0.70** → 후판으로 top-down **성립**(98작 재분석 사양 확정 근거) / r_L2G ≤ 0.30 → 후판도 불성립.
- **분해**: r_L2D − r_L2G > 0.30 → **생성 손실 지배**(투자처=프롬프트·학습) / 차이 ≤ 0.30이며 둘 다 낮음 → **정보 부족 지배**(투자처=스키마·분석).
- **r_L3 < 0.70** → 설계로 환원 불가 성분 존재 선언(씬카드 우위의 원천 규명 후속).
- r>1.0 = 성립+드리프트 신호(C1 준용). 민감도: s7 제외·작품별 r 병기(단독 통과=★보류)·S05 단독 기여.
2차 종점(탐색적·판정 불사용): 작법 5차원을 L2-G vs B에서 병기 — 깊이 상승이 과잉 정돈을 심화시키는지 관찰.

## 3. 한계·무효 조건
스코프 2작 한정(C3 준용). 저작자가 원문을 읽으므로 L2는 "사람이 원문에서 추출 가능한 정보의 상한"을 표집 — 시스템이 기획만으로 후판을 만들 수 있는가는 별개 질문(차차기). 무효: 저작자·렌더러의 정답표 열람, 봉인 후 수정, B−A<0.5.
