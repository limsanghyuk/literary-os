# 엔진(v794)–데이터베이스 연결 점검 보고 — 단계 인식 검증 + 브릿지 지도 (2026-07-28)

**계기**: 개발자 질문 — "LLM-0~1 거의 마무리, LLM-2 기획 중 데이터베이스 구축. 맞는가. 방향이 올바른가. 남은 과제=DB를 모델에 연결해 점진 완성." · 대상: 업로드 v794(v13.45.1, 88패키지) 실조사 + 허브 v14.0.0(V795) 대조.

## 1. 단계 인식 검증 — **맞다, 그리고 한 가지 좋은 소식**
- **LLM-0~1: 완료가 맞다.** v794→V795 졸업(SP-E.10, 5/5 ADOPT)으로 LLM-1(loop-C 폐회로 학습)이 실증 종결됐고, 엔진에는 전 부품이 실재한다: `generation/pass_pipeline.py`(7-pass), `critic/`(M1 자격검정·M2 NextEp·M3 분포가드·Arbitration), `learning/`(loop_c·first_training_kit), `validation/`(formula_harness·registry), `nkg/`·`drse/`.
- **LLM-2 기획 중: 맞다 — 단, 기획만이 아니라 이미 실측이 시작됐다.** 지난 이틀의 작업(기획층 카드·E-사다리·프런티어 필적 64%·《오기》 전 스택 파일럿)이 바로 LLM-2(거시 플래너: 스스로 기획·구성)의 **초기 실증**이다. 우리는 LLM-2를 문서로 기획하는 단계를 지나, 수동 가동으로 검증하는 단계에 있다.
- **DB 구축: 맞다.** 83작/97,731씬 + 수확 23,657쌍이 그 연료다.

## 2. 방향 점검 — **올바르다. 근거는 엔진 코드 자체에 있다**
`pass_pipeline.py`를 열어보면 P5 루프가 **의도적으로 비워둔 세 개의 소켓**으로 설계돼 있다:
```python
RetrieveFn = Callable[[SceneBrief], List[str]]      # brief → 참조 텍스트들
GenerateFn = Callable[[SceneBrief, List[str]], str] # (brief, rag_refs) → 초안
JudgeFn    = Callable[[str, str], str]              # (draft, ref) → 'draft'|'ref'|'tie'
```
이 세 소켓이 요구하는 것이 정확히 이번 주에 만들어 실증한 것들이다: Retrieve=**코퍼스 RAG**(F2 실측 +20%p), Generate=**프런티어+브리프**(조향 20/20·필적 64%), Judge=**쌍대 판정**(G_NO_ABSOLUTE_REWARD 준수). 엔진은 처음부터 이 연결을 기다리도록 지어져 있었고, 우리는 소켓에 꽂을 부품의 성능을 먼저 실측으로 확정한 것이다. **방향이 옳았다는 가장 강한 증거는, 따로 만든 두 갈래(엔진·데이터)가 설계 변경 없이 맞물린다는 사실이다.**

## 3. 브릿지 지도 — 남은 연결 과제 (점진 완성의 실체)
| # | 엔진 소켓 (v794 실재 모듈) | 꽂을 DB 자산 | 상태 | 
|---|---|---|---|
| **B1** | `JudgeFn` + critic 쌍대 경로 | 쌍대 프로토콜(위치무작위·후향정합 교훈 반영) | 프로토콜 확정, 코드 배선만 |
| **B2** | `RetrieveFn` ← `rag`/`nkg` | corpus_ko ChromaDB(18,358벡터)+seqcard 인접 씬 | 실증 완료(64%), 배선만 |
| **B3** | `GenerateFn` | 프런티어 어댑터(gpt-5.1/Claude) + F3 검증 프롬프트 템플릿 | 프롬프트 확정, 어댑터화 |
| **B4** | P0~P4 입력 계약(`generation/schema.py`) | WorkPlanningCard(기획층 5작+오기)·authored_arc·seqblueprint | 스키마 양쪽 존재, 매핑 1파일 |
| **B5** | `critic/critic_qualification`(M1)·`distribution_guard`(M3)의 닻 | CANONICAL 코퍼스 실 씬(현재 데모 닻 — 과대 판명 이력) | **교체 필요** |
| **B6** | `learning/loop_c`·`signal` | e2_dataset(20,835쌍, 집 로컬) + 《오기》 수정쌍(InterventionEvent) | 데이터 준비 완료 |
| **B7** | `critic/next_episode_bench`(M2)의 은닉 GT | DR-5 홀드아웃(최신작 2~5편) | **개발자 구매 결정 대기** |
**권장 순서**: B1→B2→B3(P5 루프 최소 실가동: 브리프 하나가 엔진을 통과해 씬이 나오는 것) → B4(기획 입력 개통: 《오기》 카드가 P0 입력이 되는 순간 수동 공정이 자동 공정으로) → B5 → B6 → B7. 각 단계마다 기존 게이트(pytest+G_*)로 DoD.

## 4. 정직한 주의 2건
- 업로드본은 v13.45.1(V794) — 정본은 졸업 반영된 **v14.0.0(V795, 허브)**. 회사 작업 시 허브 클론 기준으로.
- 이번 주 실증은 전부 "엔진 밖 수동 가동"이었다 — 성능은 증명됐지만 재현성·게이트 강제는 배선(B1~B4) 후에야 확보된다. 《오기》가 v1.3에서 좋아지는 것과 별개로, **v2.0부터는 엔진을 통과해 저작되는 것**이 목표여야 한다.

## 5. 결론
개발자의 인식 그대로다: **LLM-0~1 완결, LLM-2는 기획을 지나 초기 실증, DB는 연료로 축적 중, 남은 것은 연결.** 그리고 연결은 추상 과제가 아니라 위 표의 7개 소켓이다 — B1~B4만 배선되면 《오기》급 전 스택 저작이 사람 손을 거치지 않는 엔진 공정이 된다. 그것이 "점진적 완성"의 다음 마일스톤이다.
