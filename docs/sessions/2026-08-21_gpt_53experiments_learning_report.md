## 2. GPT가 R21~R46에서 밝힌 것 (우리가 몰랐던 26개 실험)

### 2-1. 계층 계획이 평면 계획을 이긴다 — R39
- 동일 입력(N−1 상태·조건부 재발·43작 검색·선택적 THICK)에서 **평면 계획기(F) vs 계층 계획기(H)**만 비교.
- H = EpisodeSynopsisPlan → 회차 축 → 유예/부채 → 종단/종료상태 → SequencePlan → ScenePlan 하향.
- **결과: H−F 중앙값 +8.5점, 6작 중 5작 우위**(사전 기준 +3). 미래 누출 0/0. 개봉 전 32파일 동결→개봉 후 바이트 불변 확인.
- **핵심 실패도 발견**: 더킹투하츠에서 F가 H를 이김. 상위 EpisodePlan이 "결별·정체 폭로·기억 회수를 유예"로 잘못 판단했는데 실제 회차는 정반대로 폭발시킴 → **Upstream Error Amplification(상위 오류 증폭)** 개념 정립. 계층은 좋은 상위 결정을 증폭하지만 나쁜 결정도 증폭한다.
- **우리 CT-13 R3 결과와 정확히 같은 방향**: 계획층이 회차 시놉시스 품질을 올린다.

### 2-2. 후보군(포트폴리오) + 선택기 — R45/R45R ★가장 중요한 재해석
- EpisodePlan을 1개가 아니라 **5개**(정상 인과 2~3 + 앙상블 변형 + 고변동/과감) 생성 후 Selector로 선택.
- **R45R(현실적 사용자 기준군 재실험)**이 기존 해석을 뒤집었다. 새 6작(공주의남자·구해줘·궁·녹두꽃·가을동화·돌아온일지매)에 **EP01~09 원문 전체 + 일반 사용자가 쓸 법한 자연어 요약**을 준 Foundation 조건을 신설.
  - U1 80.5 → U5 92.0 → **L5 97.0**
  - **Selector regret은 U5=0, L5=0** → Critic 자체의 우위는 미증명.
  - **재해석: Literary OS의 차별점은 "더 좋은 선택기"가 아니라 "더 좋은 후보 탐색공간의 구조화"**다.
- **정직성 주목**: 원문을 통째로 준 Foundation도 80.5→92.0으로 매우 강하다는 것을 인정하고, 우리 증분을 과대주장하지 않는다.

### 2-3. 정본 유사도를 성능 지표에서 제거 — R40 → R40R
- R40은 "다음 회차 정본과 얼마나 같은가"로 재서 `FAIL_AUTONOMOUS_ROLLOUT`을 선언했다.
- **R40R에서 정본 유사도를 빼고 작법 우선(craft-first)으로 재판정 → Monitor 72.5→80.5, 4/4 우위.**
- **정정 명제: 정본과 다른 창작 분기(canonical divergence)는 그 자체로 실패가 아니다.**
- → **우리 CT-11/12 결론과 완전히 같은 결론에 다른 경로로 도달**(우리는 "경계 재현 종점이 오염됐다", GPT는 "정본 유사도를 종점에서 빼라").

### 2-4. 그 밖의 확정 사항
- **R41 앙상블/톤**: 지배 플롯·적대 플롯·관계 플롯·조연·완화(코믹)·보류/퇴역의 **플롯 소유권 배분**. 단 6종을 매 회차 강제하지 않고 "왜 이번엔 쓰는가/안 쓰는가"를 계획기가 판단.
- **R42 Blueprint→Scene 재검증 PASS 4/4**: 좋은 설계도가 **동일 렌더러**의 품질을 올린다 → 렌더러는 교체 가능(우리 CT-07 결론의 독립 재현).
- **R44 검색 재현 PASS 4/4**(감사 수리 후): 기능 검색은 유용, **깊은 타작 EpisodePlan 이식은 위험**. R1 감사에서 "검색 메타데이터의 원작명"을 본문 누출로 오인한 버그를 발견하고, 원 감사를 삭제하지 않고 superseded로 보존.
- **R46 다회차 롤아웃 PASS 5/5**: 생성 EP09를 정본으로 받아 EP10~12 전개. Primary+Shadow 분기와 **Top-2 미래 기억**, Re-Critic 유효.
- **R35**: "근거 있는 과감함 ≠ 시점에 맞는 과감함"으로 Bounded Bold 거부 → **Temporal Eligibility Critic** 도입 근거.

### 2-5. 현재 GPT 엔진 파이프라인 (실험으로 승격된 것만)
```
User Materials → Narrative Ingestion & State Compiler → Thread Safety/Conditional Recurrence
→ Functional Retrieval → Grammar Abstraction → 5-way Candidate Portfolio
→ Candidate Diversity + Temporal Eligibility + Novelty Grounding → Critic → Top-2 Future Memory
→ Episode Plot Ownership/Ensemble Allocation → EpisodeSynopsisPlan → SequencePlan
→ Boundary R1 → Blueprint Contract → Frontier Renderer → Scene/Dialogue/Action
```
**핵심 결론(GPT 자체)**: 최근 실험 대부분은 **분석 DB 스키마 변경이 아니라 Planning Runtime 계약 확장**을 요구했다 → **분석 DB와 생성 Runtime 스키마를 분리 관리**해야 한다.

## 3. ★경계 표준 R1 — 우리 CT-12와의 독립 수렴

GPT의 `DRAMA_ANALYSIS_SEQUENCE_BOUNDARY_HANDOFF_MANUAL_R1`(8/17)은 우리가 같은 날 독립적으로 도달한 결론과 **거의 동일**하다.

| 항목 | 우리(CT-12 + 시퀀스 표준 v1) | GPT(경계 표준 R1) |
|---|---|---|
| 문제 정의 | "왜 여기가 경계인지 설명하는 필드가 없다" | **동일 문장**: "왜 바로 그 Scene 뒤가 경계인지 설명하는 공식 필드가 없다" |
| 헤딩(장소·시간)의 판별력 | 장소 변화만으로 끊기 금지(안티패턴) | **전수 실측으로 확인**: heading change는 경계와 내부에서 거의 동일 빈도 → 판별력 거의 없음 |
| 경계 근거 코드 | B1~B5 + boundary_reason 신설 | **B1~B7** + 별도 append-only `SequenceBoundaryEvidenceR1` |
| 등간격 금지 | 안티패턴 ①·게이트 G3(cv<0.08 경보) | **"장면 수 맞추기 위한 등분 금지, 평균 k는 prior일 뿐 quota 아님"** + G5 UNIFORMITY 진단 |
| 판정법 | "지우면 상태 서술이 바뀌는가" | **Two-Sided Test**(LEFT TERMINAL 결제 + RIGHT RESET 재활성) + **±1 Scene Challenge(최소성)** |
| 소급 감사 | CT-12D 제안 | **"CT-12D 방식"으로 명시 채택** — 우리 제안 명칭을 그대로 씀 |
| 게이트 | G1~G5 | **G1~G9**(PARTITION/EVIDENCE/TWO-SIDED/MINIMALITY/UNIFORMITY/SINGLETON/VALUE-SHIFT/PARITY/SOURCE-HOLD) |

**GPT가 우리보다 나은 점**: ①8개 상태 차원(G·K·R·P·C·M·W·L)으로 경계 근거를 더 세분 ②**Two-Sided Test와 ±1 최소성 검사**라는 구체적 판정 절차 ③기존 34작 보강을 Phase A1(결정론 스크리닝)→A2(SOURCE 감사)→A3(선택 보강) 3단으로 운영화 ④"63작은 전면 재검 없이 THICK 승격 시 함께 검증" 같은 자원 배분 원칙.
**우리가 나은 점**: ①**라벨 신뢰도를 실측**(R1 0.737 / R2 0.426 / 등분 0.704)한 유일한 근거 ②등분 재현율 전수 지도(1,814회차, 작품별 0.97~0.22) — GPT의 "등분 금지" 규칙에 **정량 근거**를 제공한다.
→ **양쪽을 합치면 표준이 완성된다**: GPT의 판정 절차 + 우리의 신뢰도 측정·층화 지표.
