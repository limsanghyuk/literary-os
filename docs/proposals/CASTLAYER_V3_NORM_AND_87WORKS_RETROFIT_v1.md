## 0. 제안명 정정 — "SceneCard 스키마 v3"는 틀린 이름이다

착수 지시는 "SceneCard 스키마 v3(인물 필드 + 인물 명부 + pov 규약)"였다. 허브 실사를 마친 결과 **이 이름을 폐기한다.** 세 결함 중 둘은 이미 스키마가 존재하고, 남은 하나는 SceneCard가 아니라 SequenceBlueprint의 문제이며, SceneCard 9키에 필드를 더하는 선택지는 2026-07-13에 이미 검토되어 기각된 바 있다.

| 결함 (측정 보고서 §8) | 실제 상태 | v3에서 할 일 |
|---|---|---|
| ① 씬별 등장인물 부재 | **스키마 있음** — `CastPresenceRecord`(10키), FROZEN 2026-07-13 | 저작 롤아웃 (스키마 개정 아님) |
| ② 인물 명부 부재 | **스키마 있음** — `EntityBridgeRecord`(9키), FROZEN 2026-07-13 | 87작 부트스트랩 + 롤아웃 |

## 1. 문제의 구조적 정의

전수 측정은 "인간 작가는 주인공 단독 서사로 구성하지 않는다"를 87작에서 확인했다(최다인물 부재 씬비율 중앙 39%, 주요 인물 중앙 3명). 그러나 그 수치는 전부 **텍스트 매칭 근사**다. SceneCard 9키 어디에도 "이 씬에 누가 있는가"가 없어, `title`·`intent_gist`·`heading`에서 이름을 긁어 추정했다. 이름이 불리지 않는 등장은 구조적으로 누락되므로 부재율은 항상 **상한 추정**이다.

즉 문제는 "복수 중심을 어떻게 볼 것인가"가 아니라 **"게이트가 검사할 값을 근사에서 정확값으로 승격시킬 수 있는가"**다. 기획 게이트 v2의 7개 하한 중 2개(부재율·주요 인물)가 근사 위에 서 있고, 그 둘이 하필 이 트랙의 핵심이다.

## 3. 규범 결정 A — SceneCard 9키는 건드리지 않는다 (확인)

`characters: []`를 SceneCard에 직접 넣는 안은 **기각한다.** 사유는 셋이 동시에 걸리기 때문이다.

1. V10 `AUTHORITY_MANIFEST.json`의 `canonical_scene_card_keys: 9`가 권위 선언이다. 필드 추가 = 권위 개정 = V11 발행.
2. `EXACT_SCHEMA_REGISTRY.json` 및 Gate A1이 **exact keyset**(누락·잉여 0)을 강제한다. 필드를 더하는 순간 기존 102,417 SceneCard 전량이 FAIL한다.
3. EXT6 계약 §1-1이 이미 같은 결론을 내렸다 — "EXT6은 기존 스키마를 수정하지 않는 보강층이다."

사이드카 배치의 실질적 이점은 **원장 불변**이다. SourceLock의 `text_sha256`이 그대로 유지되고, 인물층 저작이 실패해도 Stage01~04 정본은 오염되지 않는다.

## 4. 규범 결정 B — pov_char 표기 규약 (v3 신규)

### 4.1 실태 (14,751 시퀀스 전수)

| 항목 | 값 |
|---|---|
| 시퀀스 총수 | 14,751 |
| 공란·null | 420 (2.8%) |
| 복수 인물 표기 | 5,778 (39.2%) |
| 구분자 종류 | `·` 4,204 · `/` 1,485 · `,` 92 — **3종 혼용** |
| 복수 POV를 한 번도 표기하지 않은 작품 | **28 / 87** |

28작이 통째로 단일 POV만 쓰는 것은 내용의 차이가 아니라 저작자 습관의 차이다. 같은 다인물 수사극이 한쪽은 복수 표기, 한쪽은 단일 표기를 쓰면 이 필드로는 아무것도 비교할 수 없다. **현 상태의 `pov_char`는 통계에 사용 불가**이며, 이는 데이터가 나쁜 것이 아니라 규약이 없는 것이다.

### 4.2 규약 (v3)

| 항목 | v2 (현행) | v3 (제안) |
|---|---|---|
| 타입 | `str` (자유 표기) | `list[str]` (순서 = 시점 비중 내림차순) |
| 값 | 임의 인물명 | **EntityBridge.character_key만 허용** |
| 복수 | 구분자 3종 혼용 | 배열 원소 |
| 시점 부재 | 공란/null | `[]` (명시적 빈 배열) |
| 상한 | 없음 | 3개 초과 시 WARN (시퀀스 정의상 시점 4개는 분할 신호) |

**하위 호환**: 필드명·키 개수(18키)는 불변이므로 SequenceBlueprint 스키마 개정이 아니라 **타입·값역 정밀화**다. Gate는 `str`과 `list[str]`을 모두 수용하되, `str`은 `LEGACY_POV` WARN을 발행한다.

### 4.3 소급 정규화 — 실행 진단 결과

`tools/castlayer_v3/normalize_pov_char.py`를 87작 전량에 실행했다(무LLM).

| 진단 | 값 | 처리 |
|---|---|---|
| 시퀀스 총수 | 14,751 | — |
| `str` 타입(legacy) | 14,751 (100%) | WARN `LEGACY_POV` |
| 분해 후 명부 조인 성공 | 18,159 / 23,594 = **77.0%** | 잔여 5,435 미매칭 |
| 원소 4개 이상 | **606** | WARN (시퀀스 분할 신호) |
| 공란·null | 420 | 저작 필요 |
| 복수 POV 무표기 작품 | 28 / 87 | `pov_status: UNRELIABLE` 격리 |

구분자가 3종뿐이므로 분해 자체는 결정론적으로 완결된다. **조인 실패 23%가 핵심 잔여**이고, 이는 Tier1 명부가 CharacterArc 기반이라 아크 없는 POV 인물을 담지 못하기 때문이다 — §5.1의 계층 한계가 여기서 그대로 재현된다. Tier2 정식 명부가 들어오면 자동 해소된다.

결정론으로 못 고치는 둘:

- 공란 420건 → 저작 필요.
- 복수 POV 무표기 28작 → 재정독 필요. **자동 변환은 이 28작에 대해 "단일 POV"라는 거짓 정보를 확정시키므로, 이들은 `pov_status: UNRELIABLE`로 격리하고 통계에서 제외한다.** 격리 목록에 하얀거탑·추적자·밀회·태양의후예 등 다인물 구조가 분명한 작품이 다수 포함된 것이, 이 결측이 내용이 아니라 습관에서 왔다는 방증이다.

**주의 — 앵커 충돌**: 격리 28작에 **시크릿가든**이 포함된다. 시크릿가든은 EXT6 계약 §11이 지정한 2차 앵커다. 앵커 저작 시 pov_char 재정독을 같은 회차 작업에 묶어 처리한다.

### 5.1 계층 경계의 실증

CharacterArc에서 결정론으로 뽑은 명부가 EXT6 정식 저작의 인물을 얼마나 포착하는가 — 파일럿 24회 753개 인물-회차 레코드로 대조했다.

| scene_share_band | 결정론 명부 포착률 |
|---|---|
| DOMINANT (≥50% 씬) | **4/4 = 100%** |
| MAJOR (20~50%) | **48/48 = 100%** |
| MINOR (5~20%) | 137/185 = 74.1% |
| CAMEO (<5%) | 126/516 = 24.4% |
| 전체 | 315/753 = 41.8% |

전체 재현율 41.8%는 나쁜 수치처럼 보이지만, **누락분은 전부 하위 대역이다.** 돌아온일지매의 정독 명부 260명 중 결정론이 놓친 227명은 거지1·경찰1·과일상인 같은 단역이고, CharacterArc는 정의상 상태 변화를 가진 인물만 담으므로 이들이 없는 것이 정상이다.

기획 게이트 v2가 쓰는 임계는 ≥10%와 ≥20%다. **결정론 계층은 게이트가 보는 대역에서 100% 정확하고, 게이트가 보지 않는 대역에서만 부정확하다.** 계층 경계를 여기에 긋는다.

## 6. 실행 명세

### Tier 1 — 결정론 부트스트랩 (87작 전량, 즉시, 무LLM)

`advisory_bridge/<work>.bridge.jsonl` 생성. 등급은 `advisory_`(계약 §1-3의 3구분 중 가치증명 전 참고 등급)로 명명하여 `authored_bridge` 정본과 물리적으로 분리한다.

- 입력: `authored_chararc/` 1,640파일 (인물명 1,402 원표기)
- 병합: 끝 2자 병합키 + `/`·`(` 분해 → **1,228 레코드** (표기 감소 12.4%)
- 별칭 자동 부여: 162 레코드
- **`mapping_status=CONFLICT` 142건(11.6%)** — 병합 그룹 내 성이 다른 경우. 자동 병합하지 않고 수동 확인 대상으로 표시.
- 실행 결과: 87작 전량 생성 완료 (본 세션 실증, 산출물 로컬 보관)

이 단계만으로 전수 측정의 최대 오차원 하나가 제거된다 — 병합 없이 셌을 때 유효 인물 수가 2배로 부풀던 문제.

### Tier 1.5 — advisory_cast (선택, 결정론)

Tier1 명부의 별칭을 적용해 SceneCard 텍스트 매칭을 재실행하고 `advisory_cast/`로 저장. CastPresenceRecord 10키를 그대로 쓰되 `by="derived_textmatch_v3"`, `presence_mode` 전량 `ONSCREEN` 고정, `focality`·`speaking_status`는 판정 불가이므로 이 층에서는 `PRESENT_ONLY`/`NONSPEAKING`으로 두고 **band 계산에만 사용**한다. 산출은 여전히 상한 추정이며 문서에 항상 그렇게 표기한다.

### Tier 2 — EXT6 정식 저작 (우선순위 점증)

선행 조건 — 아래가 전부 닫히기 전에는 착수 금지:

- [ ] 교차검토 §5 항목 1~6 GPT 합의 종결
- [ ] 112상황실 삭제 (Gate B7 구현)
- [ ] 비밀의숲 01 scene 68/71 국과수분석관 보정
- [ ] 정식 CrossProviderComparisonRecord(12키, 배치 여부 포함 full join)로 조건부 κ → 공식 κ 승격
- [ ] 앵커 2차(시크릿가든)·3차(베토벤바이러스) Gate A/B/C

착수 순서: 앵커 3작 → 게이트 v2 위반 판정이 갈리는 경계 작품 → 나머지. 회차 단위로 Gate A/B ERRORS 0을 확인하고 잠근다.

## 7. 자기 점검 — 이 제안의 논리적 약점

**약점 1 · 계층 경계의 근거가 24회차뿐이다.** DOMINANT/MAJOR 100% 포착은 파일럿 24회(전체의 1.5%)에서 나온 수치이고, 그 24회는 사실상 한 작품(돌아온일지매)이다. 사극 단역 구조가 다른 장르로 일반화된다는 보장이 없다. → 앵커 2차(시크릿가든) 통과 시 이 표를 재산출하는 것을 조건으로 단다.

**약점 2 · CharacterArc 자체가 저작물이다.** 결정론 부트스트랩은 "무LLM"이지만 입력인 CharacterArc는 LLM 저작이다. 저작자가 놓친 인물은 명부에도 없다. 따라서 Tier1은 "객관적 명부"가 아니라 **"기존 저작 판단의 일관된 재정리"**다. 이 문구를 산출물 헤더에 넣는다.

**약점 3 · CONFLICT 142건의 처리를 미뤘다.** 11.6%는 무시할 수 없는 비율이고, 이 중 실제 동일인(`이은찬`/`고은찬`)과 실제 별개 인물이 섞여 있다. 자동 판정 불가이며 작품별 확인이 필요하다. 지금은 표시만 하고 넘긴다는 것을 명시적 부채로 기록한다.

**약점 4 · pov_char 28작 격리는 표본을 21% 줄인다.** 복수 POV 지표를 87작이 아니라 59작에서만 산출하게 되며, 격리된 28작이 무작위 결측이 아닐 수 있다(특정 저작 배치에 몰려 있을 가능성). → 격리 목록을 저작 배치·시기와 대조해 편향 여부를 확인하는 것을 후속 과제로 남긴다.
